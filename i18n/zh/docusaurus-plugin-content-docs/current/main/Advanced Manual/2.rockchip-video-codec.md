## 1. 视频编解码简介 {#technology-overview}

本文演示 GStreamer 硬转码、FFmpeg 软件编解码和 MPP 底层工具三种用法，适用于本地播放、录像转码及嵌入式视频开发。

H.264 / H.265 是编码格式，MP4 是封装视频和时间信息的容器；NV12 是解码后的原始像素格式。典型流程为：**读取 MP4 → 解封装与解析 → 解码 → 显示，或重新编码并保存**。

| 技术 | 作用与案例 |
| --- | --- |
| GStreamer | 组合视频管线；案例一用 MPP 硬解、硬编码为 H.264 MP4，案例二扩展到 H.265 |
| FFmpeg | 准备素材、检查文件；案例二用 `libx265` 软件编码，与硬件方案对照 |
| Rockchip MPP | 访问视频编解码硬件；案例三直接处理 NV12 帧和不带 MP4 容器的裸码流 |

## 2. 适用环境与工具安装 {#environment}

### 2.1 适用板型与镜像 {#sdk-compatibility}

ArmSoM SDK 提供以下 ARM64 镜像配置：

| 芯片 | 板型 | SDK 镜像配置 |
| --- | --- | --- |
| RK3528 | Sige1 | Debian 12 |
| RK3576 | AIM5、CM5（CM5-IO 和 CM4 Nano B IO）、Sige5 | Debian 12、Ubuntu 22.04 |
| RK3588 / RK3588S | AIM7、CM7S、LM7、Sige7、Sige7S | Debian 12、Ubuntu 22.04 |

两套系统配置均包含 MPP 和 GStreamer Rockchip 插件。其他板型请使用对应官方镜像，并按案例验证编解码与显示能力。

完整流程实测于 **CM7S + Debian 12 XFCE/X11**。HDMI 回放需登录 X11 桌面且支持 XVideo；Server 镜像可运行编解码，跳过回放。

实测版本：CM7S（RK3588S），内核 `6.1.118-rk3588`，HDMI 1080p60；GStreamer 工具包 `1.22.9-1`、Rockchip 插件 `1.14-4`、MPP `1.5.0-1`。

### 2.2 安装工具

联网并登录板端桌面，在**桌面终端**安装工具；素材在第 3 章准备。

:::tip APT 与用户权限
刚刷镜像时，先按[更新 APT 软件源](/getting-start/apt-update#fresh-image-apt)检查时间和软件源。使用 root 登录时，省略命令中的 `sudo`。

## 3. 下载示例与准备素材 {#prepare-video}

先创建板端工作目录：

```bash
mkdir -p ~/rockchip-video
```

点击顶部按钮，将 `rockchip-video-examples.tar.gz` 下载或通过 SFTP / U 盘传入**板端** `~/rockchip-video/`，然后执行：

```bash
cd ~/rockchip-video
tar -xzf rockchip-video-examples.tar.gz
bash prepare-video.sh
```

脚本从 [Blender 官网](https://download.blender.org/durian/trailer/sintel_trailer-1080p.mp4)下载《Sintel》，截取第 12 秒起的 8 秒，生成无音轨的 1080p30 H.264 短片。

| 文件 | 板端位置 | 用途 |
| --- | --- | --- |
| 原始预告片 | `~/rockchip-video/sintel-source.mp4` | 案例二另取一段画面 |
| 8 秒测试短片 | `~/rockchip-video/sintel-1080p.mp4` | 案例一、二、三的共同输入，240 帧 |

:::tip 重复运行与输出文件
短片已存在时直接继续，无需重跑脚本。GStreamer / MPP 可能覆盖同名输出，请先另存；FFmpeg 的 `-n` 拒绝覆盖。
:::

## 4. 案例一：GStreamer H.264 硬转码 {#transcode}

把短片交给 MPP 硬解，再以 6 Mbps 目标码率硬编码为 H.264，封装为 MP4。运行完成后，输出是 `~/rockchip-video/sintel-output-mpp.mp4`。

```bash
cd ~/rockchip-video
time gst-launch-1.0 -e filesrc location=sintel-1080p.mp4 ! qtdemux ! h264parse \
  ! mppvideodec ! mpph264enc bps=6000000 ! h264parse ! mp4mux \
  ! filesink location=sintel-output-mpp.mp4
```

`!` 连接各处理阶段，`time` 显示耗时；`-e` 让管线在中断时尝试发送 EOS。正常运行请等待 `Got EOS` 和命令结束，使 MP4 完成封装。

### 4.1 HDMI 回放与文件检查 {#playback-results}

在板端桌面终端执行以下命令，HDMI 会播放输出视频。`fpsdisplaysink` 在终端报告渲染帧率，`sync=true` 按视频时间播放。

```bash
gst-launch-1.0 -v filesrc location=sintel-output-mpp.mp4 ! qtdemux ! h264parse \
  ! mppvideodec ! fpsdisplaysink video-sink=xvimagesink text-overlay=false sync=true
```

检查输出文件的编码格式、尺寸、帧率和帧数，预期为 `h264`、1920×1080、`30/1`、240 帧：

```bash
ffprobe -v error -select_streams v:0 \
  -show_entries stream=codec_name,width,height,avg_frame_rate,nb_frames \
  -of default=nw=1 sintel-output-mpp.mp4
```

:::tip 显示环境
回放命令沿用桌面终端的显示地址。串口或 SSH 运行方式见第 7 章。无桌面系统可以完成转码与文件检查，跳过 HDMI 回放。
:::

### 4.2 CM7S 实测结果 {#sintel-results}

| Sintel 1080p 测试 | 结果 |
| --- | --- |
| 输出格式 | H.264、1920×1080、30 fps、240 帧、8 秒 |
| 仅硬解耗时 | 0.322 秒 |
| 硬解、硬编码与封装耗时 | 1.310 秒 |
| 输出大小 | 5,355,119 字节 |
| HDMI 回放 | 正常 EOS、退出码 0；末次周期采样为 236 帧已渲染、0 帧丢弃、平均 30.23 fps |

![CM7S 的 XFCE 桌面回放硬转码后的 Sintel 短片](/img/general-tutorial/cm7s-sintel-mpp-playback.webp)

:::tip 如何理解帧率
耗时为单次结果；回放末次周期采样早于 EOS，反映显示元件提交帧，不等于最终帧数或屏幕刷新率。
:::

## 5. 案例二：H.265 软件与硬件编解码 {#hevc}

### 5.1 FFmpeg 软件编解码

本例使用系统 FFmpeg 的 CPU 编码器 `libx265`，便于对照硬件方案。另取原预告片第 19 秒起的 4 秒画面，输出到 `~/rockchip-video/advanced/sintel-ffmpeg-hevc.mp4`。

```bash
mkdir -p ~/rockchip-video/advanced
cd ~/rockchip-video/advanced
ffmpeg -nostdin -n -ss 19 -i ../sintel-source.mp4 -t 4 -an -r 30 \
  -c:v libx265 -preset ultrafast -x265-params pools=2 -pix_fmt yuv420p sintel-ffmpeg-hevc.mp4
```

先用 FFmpeg 软件解码检查文件（成功时无报错），再用 MPP 硬解在 HDMI 回放：

```bash
ffmpeg -nostdin -v error -xerror -i sintel-ffmpeg-hevc.mp4 -f null -
gst-launch-1.0 filesrc location=sintel-ffmpeg-hevc.mp4 ! qtdemux \
  ! h265parse ! mppvideodec ! xvimagesink
```

CM7S 编码 120 帧耗时 **23.25 秒（5.16 fps）**，软件解码退出码为 0。截图为该输出文件经 MPP 回放的画面。

![CM7S FFmpeg H.265 输出回放](/img/general-tutorial/cm7s-case-2.webp)

### 5.2 GStreamer 硬件编解码 {#hevc-hardware}

使用第 3 章的 8 秒短片，替换为 `mpph265enc` 硬编码器，输出到 `~/rockchip-video/advanced/output-hevc.mp4`。本节可独立于 5.1 执行。

```bash
mkdir -p ~/rockchip-video/advanced
cd ~/rockchip-video/advanced
gst-launch-1.0 -e filesrc location=../sintel-1080p.mp4 ! qtdemux ! h264parse \
  ! mppvideodec ! mpph265enc bps=6000000 ! h265parse ! mp4mux \
  ! filesink location=output-hevc.mp4
```

完成后硬解输出文件，并核对视频信息。第一条命令的 `fakesink` 不显示窗口；正常 EOS 表示处理到文件末尾。

```bash
gst-launch-1.0 filesrc location=output-hevc.mp4 ! qtdemux ! h265parse \
  ! mppvideodec ! fakesink sync=false
ffprobe -v error -select_streams v:0 \
  -show_entries stream=codec_name,width,height,avg_frame_rate,nb_frames \
  -of default=nw=1 output-hevc.mp4
```

CM7S 两条管线均正常退出，输出为 **HEVC、1920×1080、30 fps、240 帧**。本节记录的是文件转码和无窗口硬解；上图来自 5.1 的输出。两节输入长度不同，不作为严格性能对比。

## 6. 案例三：MPP 原始帧与裸码流 {#mpp-tools}

先完成第 3 章和第 5.2 节，预留 **400 MiB** 空间。使用官方镜像 `rockchip-mpp-demos`（实测 `1.5.0-1`）中的解码工具 `mpi_dec_test` 和编码工具 `mpi_enc_test`。

### 6.1 解码与重新编码

进入输出目录，提取 H.264 裸码流，硬解为 NV12，再硬编码 60 帧：

```bash
cd ~/rockchip-video/advanced
ffmpeg -nostdin -n -i ../sintel-1080p.mp4 -an -c:v copy -bsf:v h264_mp4toannexb input.h264
mpi_dec_test -i input.h264 -t 7 -n 60 -f 0 -o decoded.nv12
mpi_enc_test -i decoded.nv12 -w 1920 -h 1080 -hstride 1920 -vstride 1080 \
  -f 0 -t 7 -n 60 -fps 30 -bps 6000000 -o encoded.h264
```

H.265 使用第 5.2 节的输出，过程相同：

```bash
ffmpeg -nostdin -n -i output-hevc.mp4 -an -c:v copy -bsf:v hevc_mp4toannexb input.hevc
mpi_dec_test -i input.hevc -t 16777220 -n 60 -f 0 -o decoded-hevc.nv12
mpi_enc_test -i decoded-hevc.nv12 -w 1920 -h 1080 -hstride 1920 -vstride 1080 \
  -f 0 -t 16777220 -n 60 -fps 30 -bps 6000000 -o encoded.hevc
```

| 参数 | 含义 |
| --- | --- |
| `-c:v copy` 与 `*_mp4toannexb` | 不重新编码，从 MP4 提取 Annex B 裸码流 |
| MPP `-t 7` / `-t 16777220` | H.264 / H.265 |
| MPP `-f 0`、`-n 60` | NV12 像素格式、处理 60 帧 |
| `-hstride`、`-vstride` | 原始帧的行步长、垂直步长；本例为 1920、1080 |

:::caution 原始帧布局
本例导出的 NV12 文件各为 186,624,000 字节，使用紧凑布局。换用其他分辨率或直接读取硬件缓冲区时，应依据实际帧元数据确定步长，不能照搬本例数值。
:::

### 6.2 检查与回放 {#mpp-playback}

<span id="61-回放-mpp-裸码流"></span>

检查两份码流，实测均为 1920×1080、60 帧。所有产物位于 `~/rockchip-video/advanced/`：

```bash
for file in encoded.h264 encoded.hevc; do
  ffprobe -v error -count_frames -select_streams v:0 \
    -show_entries stream=codec_name,width,height,nb_read_frames -of default=nw=1 "$file"
done
```

| 格式 | 解码产物 | 硬编码产物 |
| --- | --- | --- |
| H.264 | `decoded.nv12` | `encoded.h264` |
| H.265 | `decoded-hevc.nv12` | `encoded.hevc` |

直接回放 HEVC 裸码流。它没有 MP4 容器，因此无需 `qtdemux`：

```bash
gst-launch-1.0 filesrc location=encoded.hevc ! h265parse ! mppvideodec ! xvimagesink
```

## 7. 常见问题 {#troubleshooting}

| 现象 | 处理方式 |
| --- | --- |
| APT 或下载报时间、证书、源错误 | 参考[更新 APT 软件源](/getting-start/apt-update#fresh-image-apt)，先校时并检查软件源 |
| 找不到输入文件或 `advanced` 目录 | 先完成第 3 章；第 5 章用 `mkdir -p` 创建目录。`cd` 后面应是目录，不是 `.mp4` 文件 |
| `no element` 或找不到 MPP 工具 | 按下面的方法检查对应元件，使用匹配板型的官方镜像及 Rockchip 软件包 |
| 有输出但无法打开 HDMI 窗口 | 登录板端 X11 桌面，在桌面终端运行；串口/SSH 还需显示地址和访问权限 |
| MP4 无法读取 | 等待编码管线正常 EOS 后再检查；中途退出可能留下未完成封装的文件 |

<details>
<summary>检查缺失的 GStreamer 元件与 MPP 工具</summary>

`gst-inspect-1.0` 仅查询元件；出现 `Missing:` 时补齐对应插件。通用 GStreamer 工具包不包含 Rockchip 插件。

```bash
for element in qtdemux h264parse h265parse mppvideodec mpph264enc mpph265enc mp4mux fpsdisplaysink xvimagesink; do
  gst-inspect-1.0 "$element" >/dev/null || { echo "Missing: $element"; break; }
done
command -v mpi_dec_test mpi_enc_test
```

</details>

<details>
<summary>通过串口或 SSH 打开 HDMI 窗口</summary>

先在**板端桌面终端**查看显示地址：

```bash
echo $DISPLAY
```

若输出为 `:0`，可在串口或 SSH 终端设置：

```bash
export DISPLAY=:0
```

使用实际显示地址，并以有权访问桌面的用户运行；设置 `DISPLAY` 本身不会授予访问权限。

本文使用 `xvimagesink`；实测 `ximagesink` 有格式协商或丢帧问题。请确认桌面支持 XVideo。

</details>
