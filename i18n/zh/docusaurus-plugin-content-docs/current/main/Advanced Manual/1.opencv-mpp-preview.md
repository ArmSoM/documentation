## 1. OpenCV 简介 {#overview}

OpenCV 是开源的计算机视觉库，常用于读取图片和视频、转换色彩、去噪、提取轮廓和分析画面变化。在 Python 中，一张图片或一帧视频通常以 NumPy 数组表示。可以先处理单张图片，再把同样的操作应用到视频的每一帧。

本篇从图片和视频两个场景入手。图片案例先用高斯滤波减少噪声，再用 Canny 检测轮廓。视频案例可以切换灰度预览、边缘预览和运动区域预览。运动区域通过比较相邻帧的亮度来标出画面变化，适合观察固定机位下的活动。

在 Rockchip 板卡上，系统 GStreamer 调用 MPP 硬件解码本地视频，Python 端的 OpenCV 负责处理解码后的帧并在 HDMI 桌面显示。后文先演示读取灰度帧，再介绍如何直接读取 NV12 的亮度平面，并对比两种路径的板端预览速率。

### 2.2 安装与检查依赖

首次启动后，接好 HDMI，登录桌面，再接网线或在桌面连接 Wi-Fi。以下命令在板端终端执行。串口可用于输入命令，预览窗口仍显示在板端桌面。APT 命令以 root 身份执行，普通用户请在 APT 命令前加 `sudo`。

```bash
  gir1.2-gstreamer-1.0 gir1.2-gst-plugins-base-1.0
```

```bash
mkdir -p ~/cvproj
cd ~/cvproj
python3 -m venv venv
./venv/bin/python -m pip install --only-binary=:all: opencv-python==5.0.0.93
./venv/bin/python -c 'import cv2; print(cv2.__version__)'
```

```bash
for element in mppvideodec qtdemux h264parse videoconvert appsink; do
  gst-inspect-1.0 "$element" >/dev/null 2>&1 || { echo "$element missing"; break; }

done
DISPLAY=:0 xrandr --current
```

OpenCV 应输出 `5.0.0`，插件检查应显示五项 `OK`。缺少插件时，请检查板型对应的官方桌面镜像及插件包。若串口无法访问 `:0`，请在 HDMI 桌面终端执行，或使用当前桌面会话的显示地址和登录用户。

## 5. 图片与视频边缘检测 {#edge-detection}

### 5.1 静态图片边缘检测

从视频截取一帧，先用高斯滤波减少噪声，再用 Canny 提取边缘。输出图可用于查看物体轮廓和纹理边界。

```bash
cd ~/cvproj
ffmpeg -y -nostdin -ss 2 -i samples/bbb-1080p.mp4 -frames:v 1 -update 1 samples/bbb-frame.jpg
./venv/bin/python - <<'PY'
import cv2

image = cv2.imread("samples/bbb-frame.jpg")
if image is None:
    raise RuntimeError("Cannot read the sample frame")
gray = cv2.cvtColor(image, cv2.COLOR_BGR2GRAY)
edges = cv2.Canny(cv2.GaussianBlur(gray, (5, 5), 0), 60, 160)
if not cv2.imwrite("samples/bbb-edges.png", edges):
    raise RuntimeError("Cannot save the edge image")
print("IMAGE_OK", edges.shape, cv2.countNonZero(edges))
PY
```

:::tip
截取的原图保存在 `~/cvproj/samples/bbb-frame.jpg`，生成的边缘图保存在 `~/cvproj/samples/bbb-edges.png`。看到 `IMAGE_OK` 后，可以用 OpenCV 直接在 HDMI 桌面打开结果。将焦点切到图片窗口后，按任意键关闭。
:::

```bash
cd ~/cvproj
DISPLAY=:0 QT_XCB_GL_INTEGRATION=none ./venv/bin/python - <<'PY'
import cv2

image = cv2.imread("samples/bbb-edges.png", cv2.IMREAD_GRAYSCALE)
if image is None:
    raise SystemExit("Cannot read samples/bbb-edges.png")
cv2.namedWindow("Canny edges", cv2.WINDOW_NORMAL)
cv2.resizeWindow("Canny edges", 960, 540)
cv2.imshow("Canny edges", image)
cv2.waitKey(0)
cv2.destroyAllWindows()
PY
```

### 6.3 预览速率实测

HDMI-1 当前输出模式为 1920×1080、60 Hz，测试短片的输入帧率为 30 fps。下表用提交到 OpenCV 窗口的帧数除以程序耗时，包含解码、图像处理和窗口事件处理。

| 模式 | 帧数 | 耗时 | 平均预览送帧速率 |
| --- | ---: | ---: | ---: |
| 灰度预览 | 240 | 20.045 秒 | 11.97 fps |
| 运动区域预览 | 240 | 18.518 秒 | 12.96 fps |

两次测试均正常退出。表中是单次运行结果，不能据此判断两种模式的性能高低。60 Hz 是 HDMI 输出刷新率，程序送帧速率不等于显示器实际呈现的不同画面数。

## 7. 优化 1080p 预览到接近 30 fps {#preview-performance}

### 7.1 定位瓶颈

在 CM5 上通过 COM4 对同一段 1080p30 H.264 短片分段测试。每次只运行一条管线，输入均为 240 帧。分段测试以 `fakesink sync=false` 结束，不开窗口、不按播放时钟限速。

| 测试路径 | 耗时 | 平均速率 |
| --- | ---: | ---: |
| MPP 解码 → fakesink | 0.694 秒 | 345.82 fps |
| MPP 解码 → `videoconvert` 转 GRAY8 → fakesink | 19.043 秒 | 12.60 fps |
| 原 GRAY8 管线 → Python（关闭窗口） | 20.076 秒 | 11.95 fps |
| 原 GRAY8 管线 → OpenCV 窗口 | 20.045 秒 | 11.97 fps |
| NV12 亮度平面 → OpenCV 窗口 | 8.018 秒 | **29.93 fps** |

主要耗时出现在本次镜像上 `videoconvert` 转 GRAY8 的路径。只把 `waitKey` 改成 1 毫秒，原尺寸窗口也只有 12.50 fps。把缩放移到管道前、以 960×540 预览，实测为 14.31 fps。

### 7.2 直接读取 NV12 亮度平面 {#nv12-setup}

保留 MPP 的 NV12 输出，用进程内的 GStreamer `appsink` 取帧。NV12 的 Y 平面已经提供亮度数据，可以用 NumPy 按实际行步长读取，再交给 OpenCV 显示。板上测到有效宽度为 1920、步长为 1984 字节，直接按 1920 字节重排行会读错位置。脚本还根据视频帧率和单调时钟计算剩余等待时间。

使用第 3 节已解压的 `mpp_nv12_preview.py`。该脚本处理 H.264 MP4，复用 OpenCV 虚拟环境及与其 Python 版本匹配的系统 PyGObject、GStreamer 绑定：

```bash
cd ~/cvproj
DISPLAY=:0 ./venv/bin/python mpp_nv12_preview.py samples/bbb-1080p.mp4
```

```text
NV12 luma 1920 1080 stride 1984
frames=240 elapsed=8.018s fps=29.93
```

优化版保持 1920×1080 预览，完整处理 240 帧，退出码为 0。29.93 fps 是程序向窗口送帧的平均速率，HDMI 输出模式仍是 60 Hz。这个数值也包含播放节奏控制。改动只涉及 Python 和 GStreamer 管线。

### 7.3 边缘检测与运动区域实测 {#nv12-modes}

同一份脚本可用 `--mode gray`、`--mode edges` 或 `--mode motion` 切换预览。边缘模式在 Y 平面上做高斯滤波和 Canny 检测。运动模式对相邻的滤波帧求绝对差，再用阈值 25 生成运动掩膜。三种模式共用 MPP 硬解和按源视频帧率控制的预览循环。

使用压缩包中的 NV12 脚本，在 CM5 的 HDMI 桌面运行以下命令。测试使用第 4 节生成的同一段 1080p30 短片。

```bash
cd ~/cvproj
for mode in gray edges motion; do
  DISPLAY=:0 ./venv/bin/python mpp_nv12_preview.py \
    samples/bbb-1080p.mp4 --mode "$mode" || break
done
```

| 模式 | 原 GRAY8 管线 | NV12 管线 | 帧数 |
| --- | ---: | ---: | ---: |
| 灰度预览 | 11.97 fps | 29.94 fps | 240 |
| 边缘检测 | 13.29 fps | 29.93 fps | 240 |
| 运动区域 | 12.59 fps | 29.94 fps | 240 |

三种 NV12 模式均正常退出。边缘检测和运动区域模式的耗时均为 8.017 秒（保留三位小数）。

表中是向 OpenCV 窗口提交的平均速率。NV12 版本按输入的 30 fps 节奏运行，因此这些数字反映预览表现，不能用于推算算法的最大吞吐量。灰度的 GRAY8 数据来自第 7.1 节。

### 7.4 CM5 与 AIM7 实测对比 {#board-preview-comparison}

两块板卡均使用同一段 1920×1080、30 fps、240 帧的 H.264 视频和手册下载版脚本。AIM7 在 Ubuntu 22.04.5 GNOME/X11 上也成功生成并打开了 1080p Canny 边缘图。两块板卡的 HDMI 输出模式均为 1080p、60 Hz。

| 预览模式 | CM5 · Debian 12 XFCE | AIM7 · Ubuntu 22.04 GNOME/X11 |
| --- | ---: | ---: |
| 基础 GRAY8 灰度 | 11.97 fps | 5.68 fps |
| NV12 灰度 | 29.94 fps | 29.95 fps |
| NV12 边缘检测 | 29.93 fps | 29.95 fps |
| NV12 运动区域 | 29.94 fps | 29.96 fps |

AIM7 的四种预览均处理完 240 帧，退出码为 0。数值为程序向窗口送帧的平均速率。NV12 版本按源视频节奏播放，两块板卡使用的系统和桌面也不同，因此这组数据用于说明各自实测配置下的预览效果。

**重刷 Debian 12 后复测。** CM5 从安装依赖和创建虚拟环境开始按本文操作。预置镜像站无法连接时，使用 [APT 指南](/getting-start/apt-update#fresh-image-apt)中的 Debian 官方 HTTPS 源。1080p Canny 边缘图成功生成并在 HDMI 桌面打开。基础灰度为 11.91 fps，NV12 灰度、边缘和运动区域依次为 29.90、29.92 和 29.93 fps，四种模式均处理 240 帧。这些数值为程序向窗口送帧的平均速率。
