## 1. OpenCV 简介 {#overview}

OpenCV 是开源的计算机视觉库，常用于图片处理、轮廓提取和视频分析。Python 中的图片通常以 NumPy 数组表示，因此可以先处理一张图片，再将同样的操作应用到视频的每一帧。

本文提供四种效果：**图片边缘检测、视频灰度预览、视频边缘检测、运动区域预览**。视频由系统 GStreamer 调用 Rockchip MPP 硬件解码，OpenCV 负责处理和显示。默认使用已有的 NV12 优化脚本，直接读取亮度平面，减少额外的色彩转换。

### 1.1 适用板型与系统 {#sdk-board-configurations}

环境准备脚本面向 **ARM64 Debian 12、Ubuntu 22.04**，按系统版本和依赖检查，不绑定 CM5。使用官方桌面镜像，连接 HDMI、登录桌面并联网；GNOME 建议使用与实测一致的 X11 会话。

ArmSoM SDK 的多个板型共用 Debian、Ubuntu rootfs 构建目录，已有配置如下。视频案例还需要镜像提供对应的 MPP 插件和驱动，由准备脚本检查插件能否加载，实际解码在运行案例时验证。

| 芯片 | SDK 板型配置 | SDK 系统配置 |
| --- | --- | --- |
| RK3528 | Sige1 | Debian |
| RK3576 | AIM5、CM5（CM5-IO 和 CM4 Nano B IO）、Sige5 | Debian、Ubuntu |
| RK3588 / RK3588S | AIM7、CM7S、LM7、Sige7、Sige7S | Debian、Ubuntu |

### 1.2 已实测环境

| 板卡 | 系统与桌面 | 内核 | Python |

## 2. OpenCV 应用场景 {#applications}

OpenCV 既可以用于单张图片处理，也可以构建相机实时视觉应用。它提供图像变换、特征提取、相机标定、视频分析等基础能力，还可以结合训练好的模型执行检测和识别。

| 应用场景 | OpenCV 的作用 | 典型用途 |
| --- | --- | --- |
| 图像处理与增强 | 缩放、滤波、色彩转换、阈值分割和形态学处理 | 图片预处理、去噪、前景提取 |
| 工业视觉 | 边缘与轮廓提取、模板匹配、几何测量 | 零件定位、外观检测、尺寸测量；通常需要标定及稳定光照 |
| 目标检测与跟踪 | 结合传统方法或模型检测目标，再分析连续帧位置 | 人脸检测、车辆分析、目标跟随 |
| 文字与文档处理 | 校正倾斜、透视变换、二值化和区域提取 | 配合 OCR 引擎处理票据、仪表读数、文档扫描 |
| 相机标定与机器人视觉 | 求取相机参数、畸变校正、特征匹配和立体视觉 | 双目测距、视觉定位、机器人感知 |
| 视频分析 | 帧差、背景建模、光流和运动估计 | 固定机位变化检测、运动分析、视觉应用原型 |

本文的图片和视频边缘检测、运动区域预览，是这些应用的基础练习，并不直接构成完整的检测或识别系统。在 ArmSoM 上可结合 MPP 处理视频解码，进一步结合 RKNN 开发 NPU 推理应用；使用 OpenCV 本身并不代表算法会自动运行在 NPU 上。

## 3. 下载与环境准备 {#environment}

<span id="python-example" />

在**板端桌面终端**创建项目目录：

```bash
mkdir -p ~/cvproj
```

点击文章开头的“下载 OpenCV 示例压缩包”，将文件放到板端 `~/cvproj/`，文件名保持为 `opencv-examples.tar.gz`。如果浏览器保存到了“下载”目录，先用文件管理器移入项目目录；如果在电脑上下载，可通过 U 盘或 SFTP 传到板端该目录。

随后解压并安装环境。普通用户直接运行 `bash setup.sh`，脚本仅在安装系统依赖时请求 `sudo`；若桌面本身以 root 登录，也可直接运行。

:::tip 首次准备
准备过程会安装 APT 依赖。刚刷镜像时，系统时间或软件源异常的处理方法见[更新 APT 软件源](/getting-start/apt-update#fresh-image-apt)。不要使用 `sudo bash setup.sh` 为普通桌面用户创建环境。
:::

```bash
cd ~/cvproj
tar -xzf opencv-examples.tar.gz
bash setup.sh
```

`setup.sh` 自动安装缺少的依赖、建立独立 `venv`、安装 `opencv-python==5.0.0.93`（导入版本为 5.0.0），检查 MPP 和 Python GStreamer 绑定。脚本只安装和检查环境，不下载视频、不截取短片或生成图片。

看到 `ENV_READY` 表示环境安装完成，接下来按第 4 章准备素材。若提示显示不可用，请回到已登录的 HDMI 桌面终端运行案例。安装中断后可重新执行 `bash setup.sh`，已安装的依赖和匹配的 OpenCV 环境会复用。

| 文件 | 用途 |
| --- | --- |
| `setup.sh` | 安装和检查运行环境 |
| `image_edges.py` | 将本文原有图片处理及显示代码整理成可运行文件 |
| `mpp_nv12_preview.py` | 原有 NV12 视频 demo，支持三种模式 |
| `mpp_preview.py` | 原有基础灰度 demo，用于性能对比 |

:::tip 文件保存位置
项目在 `~/cvproj/`，下一章将素材保存到 `~/cvproj/samples/`。`~` 表示运行准备脚本的用户主目录，例如 root 对应 `/root`。重新打开终端后，先执行 `cd ~/cvproj`，再运行所需案例。
:::

## 4. 准备测试素材 {#samples}

环境安装完成后，单独准备本章的视频和图片素材。以下命令在板端执行，不需要重新运行 `setup.sh`。若只使用自己的 H.264 MP4 运行视频案例，可以跳过本章，并在视频命令中替换输入路径。

### 4.1 下载视频

下载 30 秒的 1080p 样片，保存到 `~/cvproj/samples/bbb-source.mp4`：

```bash
cd ~/cvproj
mkdir -p samples
curl -fL --retry 3 https://raw.githubusercontent.com/renesas-rz/media/main/Big_Buck_Bunny/big_buck_bunny_1080p_30fps_30s.mp4 \
  -o samples/bbb-source.mp4
```

### 4.2 截取测试短片

从第 12 秒截取 8 秒，使用 H.264 编码并去掉音频，生成与实测相同的 **1920×1080、30 fps、240 帧**短片。`-ss 12` 指定起点，`-t 8` 指定时长，`-an` 表示不保留音频。

```bash
ffmpeg -y -nostdin -ss 12 -i samples/bbb-source.mp4 -t 8 -an \
  -c:v libx264 -preset ultrafast -pix_fmt yuv420p samples/bbb-1080p.mp4
```

### 4.3 提取测试图片

从短片第 2 秒提取一帧，供图片边缘检测使用：

```bash
ffmpeg -y -nostdin -ss 2 -i samples/bbb-1080p.mp4 -frames:v 1 -update 1 samples/bbb-frame.jpg
```

:::tip 素材位置
原视频为 `~/cvproj/samples/bbb-source.mp4`，测试短片为 `~/cvproj/samples/bbb-1080p.mp4`，测试图片为 `~/cvproj/samples/bbb-frame.jpg`。可以在桌面文件管理器中打开查看。素材只需准备一次；重复执行上述 FFmpeg 命令会覆盖同名输出文件。
:::

素材为 Blender Foundation 的 *Big Buck Bunny*（© 2008，[CC BY 3.0](https://creativecommons.org/licenses/by/3.0/)），下载自[测试素材仓库](https://github.com/renesas-rz/media/tree/main/Big_Buck_Bunny)。文中截图为节选或处理后的画面。

## 5. 图片边缘检测 {#edge-detection}

读取样片截取的一帧，转换为灰度，用高斯滤波减少噪声，再用 Canny 提取轮廓。执行一条命令，保存结果并打开预览窗口：

```bash
./venv/bin/python image_edges.py
```

终端显示 `IMAGE_OK (1080, 1920)`、非零像素数量和输出路径。焦点位于图片窗口时，按任意键关闭。

| 内容 | 文件路径 |
| --- | --- |
| 输入图片 | `~/cvproj/samples/bbb-frame.jpg` |
| 输出边缘图 | `~/cvproj/samples/bbb-edges.png` |

![板端生成的 Canny 边缘图（缩小展示）](/img/general-tutorial/rk3576-opencv-edges.webp)

<details>
<summary>只生成图片，不打开窗口</summary>

```bash
./venv/bin/python image_edges.py --no-display
```

生成后可在桌面文件管理器中打开 `~/cvproj/samples/bbb-edges.png`。

</details>

## 6. 视频处理 {#test-video}

<span id="nv12-setup" />
<span id="nv12-modes" />

以下三个案例共用包内原有的 NV12 脚本，**选择一个模式执行即可**。按 `q` 或 `Esc` 提前退出；用于核对帧数时，请等待视频完整播放结束。

### 6.1 灰度预览

直接显示 MPP 解码后 NV12 数据中的 Y 亮度平面：

```bash
./venv/bin/python mpp_nv12_preview.py samples/bbb-1080p.mp4 --mode gray
```

### 6.2 边缘检测

对每帧亮度数据执行高斯滤波和 Canny，显示物体轮廓：

```bash
./venv/bin/python mpp_nv12_preview.py samples/bbb-1080p.mp4 --mode edges
```

### 6.3 运动区域检测

计算相邻滤波帧的亮度差，以阈值 25 标出变化区域：

```bash
./venv/bin/python mpp_nv12_preview.py samples/bbb-1080p.mp4 --mode motion
```

:::tip 观察效果
运动模式中白色表示变化较大的区域，适合固定机位。镜头移动也会让背景被标亮，这不是物体识别或目标跟踪。
:::

完整播放标准样片后，终端应显示 `frames=240`，并打印耗时和平均送帧速率。提前关闭窗口时帧数会少于 240；速度取决于板型和运行环境。

:::tip 视频与结果位置
下载的原视频为 `~/cvproj/samples/bbb-source.mp4`，测试短片为 `~/cvproj/samples/bbb-1080p.mp4`。可以在桌面文件管理器中打开短片查看彩色原画。三种视频效果均在窗口实时显示，**不另存处理后的视频**。
:::

<details>
<summary>使用自己的视频</summary>

将输入路径替换为本地 **H.264 编码的 MP4**。路径包含空格时保留引号：

```bash
./venv/bin/python mpp_nv12_preview.py "/home/用户/Videos/test.mp4" --mode edges
```

这是 NV12 demo 的输入要求，不能仅凭 `.mp4` 后缀判断编码。H.265 等格式不在该 demo 的处理范围内。

</details>

## 7. 实测结果与实现原理 {#results}

<span id="board-test-output" />

### 7.1 板端效果与帧率 {#board-preview-comparison}

下表保留现有 demo 的板端测试记录。两块板卡均使用同一段 1080p30、240 帧样片，HDMI 输出模式为 1080p、60 Hz。图片案例均成功生成并打开了 1920×1080 边缘图。

| 预览模式 | CM5 · Debian 12 XFCE | AIM7 · Ubuntu 22.04 GNOME/X11 |
| --- | ---: | ---: |
| 基础 GRAY8 灰度 | 11.97 fps | 5.68 fps |
| NV12 灰度 | 29.94 fps | 29.95 fps |
| NV12 边缘检测 | 29.93 fps | 29.95 fps |
| NV12 运动区域 | 29.94 fps | 29.96 fps |

:::note 帧率含义
这里是程序提交给 OpenCV 窗口的平均送帧速率，包含播放节奏控制，不是显示器实际呈现帧数或算法最大吞吐量。两块板的系统、桌面不同，这组数据用于说明各自配置下的预览效果。
:::

下图为 CM5 上原基础灰度 demo 的 HDMI 桌面实测截图，用于展示灰度效果，不是新增准备脚本的测试记录。

![RK3576 OpenCV 1080p 灰度预览实测截图](/img/general-tutorial/rk3576-opencv-mpp-preview.jpg)

CM5 重刷 Debian 12 后的既有复测中，基础灰度为 11.91 fps，NV12 灰度、边缘和运动区域分别为 29.90、29.92、29.93 fps；四种预览均处理 240 帧并正常退出。

### 7.2 为什么默认使用 NV12？ {#preview-performance}

基础版通过 `videoconvert` 将解码结果转换为 GRAY8。CM5 的分段测试显示，主要耗时出现在这条转换路径。NV12 已包含亮度数据，优化版通过进程内 GStreamer `appsink` 获取缓冲区，用 NumPy 按实际行步长读取 Y 平面，再交给 OpenCV。

例如，CM5 实测画面宽度为 1920，但行步长为 1984 字节，不能按紧密排列的 1920 字节重排行。原 NV12 demo 已处理行步长，并按源视频帧率控制播放节奏，无需修改 SDK 或重新编译 OpenCV。

<details>
<summary>查看原有分段测试及基础版对比命令</summary>

分段测试每次运行一条管线，输入均为 240 帧。`fakesink sync=false` 表示不显示画面，也不按播放时钟限速。

| 测试路径 | 耗时 | 平均速率 |
| --- | ---: | ---: |
| MPP 解码 → fakesink | 0.694 秒 | 345.82 fps |
| MPP 解码 → GRAY8 → fakesink | 19.043 秒 | 12.60 fps |
| GRAY8 管线 → Python（关闭窗口） | 20.076 秒 | 11.95 fps |
| GRAY8 管线 → OpenCV 窗口 | 20.045 秒 | 11.97 fps |
| NV12 亮度平面 → OpenCV 窗口 | 8.018 秒 | 29.93 fps |

CM5 的另一组模式对比中，GRAY8 边缘和运动区域分别为 13.29、12.59 fps，NV12 分别为 29.93、29.94 fps，均处理完 240 帧。不同单次运行的数据不用于推断模式性能排名。

基础脚本保留在压缩包中，可选择运行，日常使用不需要先执行它：

```bash
./venv/bin/python mpp_preview.py samples/bbb-1080p.mp4
```

</details>

## 8. 常见问题 {#troubleshooting}

| 现象 | 处理方法 |
| --- | --- |
| 准备脚本在 APT 阶段失败 | 按 [APT 指南](/getting-start/apt-update#fresh-image-apt)处理时间或软件源问题，再执行 `bash setup.sh` |
| 样片下载失败 | 检查板端网络及原站可达性，再执行第 4.1 节的下载命令；下载成功后继续截取短片和图片 |
| 提示缺少 `mppvideodec` | 确认使用对应板型的官方桌面镜像及配套 Rockchip MPP 插件，单独安装 OpenCV 不会提供此插件 |
| 找不到脚本或样片 | 先执行 `cd ~/cvproj`，确认已解压，并完成环境安装和第 4 章的素材准备 |
| Qt、display 或窗口打开失败 | 在已登录的 HDMI 桌面终端运行，GNOME 可选择 Xorg/X11 会话；图片案例可先加 `--no-display` 验证保存 |

<details>
<summary>需要进一步排查时使用的命令</summary>

查看 OpenCV 版本：

```bash
./venv/bin/python -c 'import cv2; print(cv2.__version__)'
```

检查系统是否提供 MPP 解码插件。这条命令只查看插件信息，不会播放视频：

```bash
gst-inspect-1.0 mppvideodec
```

在桌面终端查看显示输出和分辨率：

```bash
xrandr --current
```

通过串口或 SSH 运行时，需先登录板端图形桌面，并使用有权访问该桌面的用户及实际显示地址。在**板端桌面终端**执行以下命令查看显示地址；直接在桌面终端运行案例通常无需手动设置。

```bash
echo $DISPLAY
```

</details>
